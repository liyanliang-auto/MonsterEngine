# MonsterEngine 手机采集、静态 3DGS 训练与端侧渲染未来计划

日期：2026-10-18（北京时间）。状态：未来实施计划，未启动开发或完成真机验收。

## 1. 目标与现状

目标是让用户用 Android 手机采集一个静态场景，最终在同一手机上用 MonsterEngine 查看可交互的 3DGS 模型。实施分两阶段：先完成手机采集、桌面/服务器训练、模型回传和手机渲染的产品闭环；再研究全程离线的手机 Vulkan 训练。第二阶段不作为第一阶段上线的前置条件。

当前仓库已有 Android 客户端、训练完成的 Gaussian PLY 导入、手机端 LOD 构建和 Vulkan 渲染实现。LOD 构建是已有高斯的组织与分页，不是从影像训练高斯。相机采集/位姿记录、影像训练、训练任务传输与回传尚无完成证据；物理 Android 手机的渲染和性能验收也仍待进行。具体源码边界见 [CODE_WIKI.md](../../CODE_WIKI.md) 和 [android/README.md](../../android/README.md)。

Mobile-4DGS 的公开训练路径依赖 CUDA/PyTorch，其移动端展示代码用于播放训练结果，不能据此认定 Android 本地训练已现成可用。LCC Scan 展示了手机扫描产品流程，但公开信息不足以证明训练全部在手机离线完成。开源端侧训练实验说明技术方向可行，不等于现有代码可直接接入 MonsterEngine，也不构成目标机型的时间、内存或画质承诺。引用：[Mobile-4DGS](https://github.com/xiaobiaodu/Mobile-4DGS)、[mobile-4dgs-project](https://github.com/xiaobiaodu/mobile-4dgs-project)、[msplat](https://github.com/rayanht/msplat)、[Voxelio iOS demo](https://github.com/Voxelio-app/ios-gaussian-splatting-demo)、[LCC Scan](https://apps.apple.com/us/app/lcc-scan/id6751404953)。复用代码前逐项核对许可证；参考算法或产品行为不等于获得代码商用许可。

本计划只覆盖**静态**物体/场景的单手机采集。单目动态视频重建为可自由视角播放的 4DGS，需要处理时变几何、遮挡和跨时间匹配，另立研究课题；文章中的实时播放、模型体积或多机位动态示例，不是单手机端侧训练能力的证据。

## 2. 阶段一：采集到手机渲染的产品闭环

### 2.1 选定一个可复现的首批场景

先选纹理较丰富、刚性、非反光的小物体，保持物体静止，让手机围绕物体移动。记录机型、镜头、光照、距离、视频时长和采样帧数；排除大面积透明/镜面、运动物体和明显运动模糊。明确首批手机与训练工作站/服务器的配置，避免把演示条件误写成普遍支持范围。

### 2.2 Android 采集与位姿包

- 实现带引导的采集流程，保存原始视频或可追溯的抽帧源，并生成训练用关键帧。优先验证 ARCore 跟踪与相机帧的时间同步；必要时用摄影测量/SfM 在桌面端重估或细化位姿。ARCore 位姿是初值，不保证直接满足训练质量。
- 每帧保留图像、时间戳、相机内参、畸变/裁剪和方向信息、`T_world_camera` 的坐标约定、跟踪质量与图像哈希；记录采集会话 ID、格式版本和设备/镜头身份。明确米制或无量纲尺度、左右手系、矩阵行列约定，训练和渲染转换只在一个定义好的边界发生。
- 拒绝或标记模糊、过曝、位姿丢失、重复视角和帧/位姿错配；允许采集者在上传前预览覆盖度并重拍。原始采集及失败原因留在本机，上传需用户明确触发，并提供删除路径。
- 先用一个版本化的采集包及离线校验器约束字段、数量、大小和哈希。采集包与现有 `.monsterlod` 场景包职责不同，不共用其 schema。

### 2.3 桌面/服务器训练与导出

- 建立可复现的静态 3DGS 基线：位姿校验/必要的 SfM 修正、训练、质量筛查、导出。记录训练代码版本、依赖/许可证、输入包哈希、参数、硬件、耗时与输出模型哈希。
- 导出 MonsterEngine 可读的 Gaussian PLY，逐项核对 `x/y/z`、`f_dc_0..2`、`opacity`、`scale_0..2`、`rot_0..3` 和可选连续的 `f_rest`；校验 opacity/log-scale 的激活约定、四元数、SH 次序及坐标变换。普通点云 PLY 不能冒充训练完成的 Gaussian PLY。
- 首版可先用人工发起的本地文件传输打通流程，再接自动上传、任务状态和下载；服务器任务需要失败重试、输入/输出校验、存储期限与删除策略。网络失败不得破坏手机本地采集数据或已导入场景。
- 回传后走现有 Android 私有 staging、原生校验及原子发布路径。小模型直接导入；超出直接渲染预算时由已有 LOD 构建/导入路径处理。训练完成和手机可渲染分别报告，不能以桌面截图替代手机结果。

### 2.4 阶段一验收与交付

在选定的实体手机上，从应用采集同一个物体，到桌面/服务器产出模型、回传、导入、重新打开并交互渲染，完整走通一次成功路径和至少一次失败恢复路径。留存采集包/模型/应用构建身份、位姿与帧数统计、训练日志、导入校验、设备/驱动信息，以及同场景的手机渲染截图或读回。使用未参与训练的视角检查形状、颜色、漂浮点和空洞；画质门限在测试前与基线图像一起固定，不能只凭“非黑屏”通过。

阶段一完成后应有：采集包 schema 与校验器、Android 采集流程、可复现训练/导出脚本或服务、回传导入流程、端到端运行记录和已知失败场景。若位姿不稳定，先修复采集/标定/SfM；若模型格式失败，先修复转换契约；若手机渲染失败，归因于设备能力、预算或渲染路径，不把问题归咎于训练本身。

## 3. 阶段二：严格离线 Android/Vulkan 训练原型

### 3.1 前置条件与实验范围

取得一台**明确型号和系统版本的物理 Android 手机**，记录 SoC/GPU、Vulkan 设备与驱动、可用特性、RAM、页大小、电池/散热状态及实际运行的 APK/Shader 身份。选阶段一已经成功重建的小型静态物体和同一采集包，预先限定帧数、最长边、初始点和高斯数量、训练迭代/最长运行时间及磁盘上限。初始数值由设备基线和小样本内存剖析决定，逐级扩大，不把限制写成所有机型的能力承诺。

现有 768 MiB 聚合上限只是 Android Viewer/LOD 的临时开发准入策略，**不是测得的手机可用内存或端侧训练预算**。训练要单独测 Java、native、GPU 与驱动分配，并考虑训练和渲染之间的资源退休；预算应由真机测量和安全余量确定。

### 3.2 原型实现路径

1. 固定输入包，先在桌面用同一小样本取得可比较的静态重建和参考图；确定初始化点/位姿来源，避免把桌面生成的高斯权重误当作手机从零训练。
2. 在 Android 上实现最小可运行训练闭环：输入解码与缓存、初始高斯、前向投影/损失、梯度、优化器更新、检查点和模型导出。以 Vulkan Compute 的实际设备能力为约束，逐项验证反向传播、梯度累积、同步、数值精度和内存布局；不能把已有推理/渲染 shader 当作训练实现。
3. 训练任务先在应用前台、可取消条件下运行；明确与 Viewer 共享 GPU/内存时的独占或切换规则。检查点写入私有目录并验证中断恢复，导出后走现有模型校验/导入路径。后台长任务能力需另按 Android 平台限制和设备行为验收。
4. 在飞行模式下从采集包开始运行，不连接服务器，不读取预先训练好的 Gaussian 权重；保留系统网络状态、日志和输入/输出哈希作为离线证据。允许应用内已安装的算法代码和通用资产，但需在实验记录中列明。

### 3.3 测量方法与继续条件

同一设备、场景、帧集、画质设置和初始电量/环境条件下至少重复多次，分别记录端到端耗时及各阶段耗时、峰值进程 RSS/PSS、可观测 Vulkan 分配或预算、存储峰值、电量、热状态/可用温度传感器、降频或中断、训练后模型大小与高斯数。温度传感器不可用时明确标记，不用主观手感补数。训练与渲染测量分开，记录是否出现 OOM、device lost、系统杀进程或明显画质退化。

用未参与训练的视角与阶段一桌面基线比较几何完整性、颜色、伪影和手机实际渲染结果；测试前约定可接受的时间、内存、温升与画质门限。只有在飞行模式真机运行成功、可重复达到这些门限、取消/恢复可控、输出可被 MonsterEngine 正常导入渲染时，才扩大帧数/分辨率/高斯规模或讨论产品化。否则保留阶段一产品闭环，记录瓶颈并重新评估设备或算法路线。

## 4. 实施顺序与依赖

| 里程碑 | 依赖 | 可审查的产物 |
| --- | --- | --- |
| P0 设备与数据契约 | 实体手机、采集样例 | 设备能力记录、采集包 schema、坐标/时间戳约定、隐私与授权清单 |
| P1 采集与位姿验证 | P0 | Android 采集包、质量报告、桌面可重估位姿的样例 |
| P2 桌面训练与格式转换 | P1 | 可复现训练记录、合规代码/依赖清单、可校验 Gaussian PLY |
| P3 回传与手机渲染闭环 | P2、现有 Android Viewer 实际真机验证 | 端到端演示、失败恢复记录、独立视角画质证据 |
| R0 离线训练可行性剖析 | P3、固定真机/小场景 | 设备能力、训练算子/内存设计、预注册实验门限 |
| R1 Vulkan 训练原型 | R0 | 飞行模式训练 APK、检查点/模型、重复测量与继续/停止结论 |

本计划不自动启动实现流水线，也不表示以上里程碑已完成。实施时以当时源码、构建结果和真实设备记录更新状态；原 Android 方案中的历史“未完成”文字可能滞后，应以当前源码和匹配构建证据为准。
